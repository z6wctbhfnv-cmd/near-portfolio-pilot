Запишите 2–3 минуты по [DEMO_SCRIPT.md](DEMO_SCRIPT.md): `npm run setup`, затем `npm run dev`, сайт на http://localhost:3000, окно инкогнито. Запасной вариант: запись терминала с `npm run tour`.
2. **Пост в X** с этим видео. Текст в [SUBMISSION.md](SUBMISSION.md). В посте обязательно: «Built at NEAR HACKATHON», `@NEARProtocol`, `#NEARHackathon`. Ссылку на репозиторий — первым ответом.
3. **Форма** на https://nearhackathon.com/#apply. Поля и текст «What did you build?» — в [SUBMISSION.md](SUBMISSION.md).
   - NEAR wallet: `larperr.near`.
   - **Website оставить пустым**: заполненное поле отклоняет заявку.
   - Поставить галочку согласия.
   - Подать **один раз**: повтор с тем же репозиторием отклоняется. Исправления потом только через https://nearhackathon.com/request-changes.
4. **После подачи** не трогайте `main` до 18 ноября и держите репозиторий публичным.

## Если хотите живой сайт (не обязательно, но плюс)

Подключить Vercel к этому репозиторию без прав владельца нельзя. Делайте **форк** к себе и импортируйте форк в свой Vercel:

- проект бэкенда: корень `backend/` (есть `vercel.json`, Cron, база Turso через `TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN`);
- переменные: `PILOT_MASTER_KEY` (любая длинная случайная строка), `CRON_SECRET`, по желанию `NEARAI_API_KEY`; список в `.env.example`;
- проект сайта: корень `frontend/`, переменная `NEXT_PUBLIC_API_BASE` = адрес бэкенда.

Поле Website в форме всё равно оставьте пустым. Ссылку на живой сайт можно дать в посте и в README.

## Правила работы

- Перед пушем в `main` и слиянием PR запускайте `scripts/deploy-check.sh` (проверяет ветки друг друга, сайт и контракт).
- Ключей в репозиторий не класть. `.env` в `.gitignore`.
